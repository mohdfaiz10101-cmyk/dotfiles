# /claude-rules-audit

审计 CLAUDE.md 中所有标记为 MUST 的规则，评估实际执行率，将"内部推理"型规则升级为强制输出。

## 用法

```
/claude-rules-audit [--dry-run] [--full]
```

- `--dry-run`: 只输出审计结果，不修改 CLAUDE.md
- `--full`: 包含所有规则（不仅是 MUST 规则）

## 审计流程

### Step 1: 提取所有 MUST 规则

```bash
grep -n "MUST\|死规则\|强制" ~/CLAUDE.md
```

对每条规则标注：
- 规则ID（行号 + 简称）
- 执行机制（内部推理 / 强制输出标签 / Hook）
- 可观测性（用户可见 / 不可见）

### Step 2: 分类规则

| 类型 | 特征 | 执行率 |
|------|------|--------|
| 死规则 | 依赖"内部推理"，无输出 | ~0% |
| 建议级 | 有输出但可跳过 | ~70% |
| 强制标签 | `[TAG]` 格式，必须输出 | ~85% |
| Hook 层 | 机器执行，exit 2 阻塞 | ~99% |

### Step 3: 升级方案

对每条"死规则"或"建议级"规则：

1. **改为强制输出标签**（L2 升级）：
   - 确定标签名：`[协议名]`
   - 确定输出格式：`[TAG] 结果: 详情`
   - 添加"死规则"标记和"禁止静默跳过"文字
   - 添加失败计数器引用

2. **建议 Hook 升级**（L3 升级）：
   - Stop Hook：会话结束前 grep 检查输出中是否有该标签
   - PreToolUse Hook：文件写入前检查相关前置条件
   - 写入 `exit 2` 阻塞逻辑

### Step 4: 输出审计报告

```
╔════════════════════════════════════════════════════╗
║  CLAUDE.md 规则审计报告                              ║
║────────────────────────────────────────────────────║
║  总规则数: N                                        ║
║  MUST 规则: M                                       ║
║  死规则: X  建议级: Y  强制标签: Z  Hook: W         ║
║  需升级: K 条                                       ║
╚════════════════════════════════════════════════════╝
```

## 强制输出标签设计模式

### 标准格式
```
[TAG] 结果内容
```

### 三种结果
- 命中/已执行 → `[TAG] ✅ 详情`
- 未命中/跳过 → `[TAG] SKIP: 原因`（不允许省略）
- 失败 → `[TAG] FAIL: 原因`

### 失败计数器
- 同一标签连续 3 次未输出 → 写入 lessons-learned.md
- 连续 5 次 → 建议 Hook 升级

## 注意事项

- **不要删除任何规则** — 只升级执行机制
- **保持标签名全局唯一** — 避免冲突
- **每条规则必须有一个可 grep 的标签** — 不可见的规则等于不存在
- **先 dry-run 确认** — 审计结果给用户确认后再修改 CLAUDE.md
- **修改后验证** — `grep -c '\[TAG\]' CLAUDE.md` 确认标签存在
