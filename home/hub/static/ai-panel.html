🛠️ 系统排查与维护清单

整合 SRE 黄金信号 + USE 方法 (Brendan Gregg) + Linux 经典排查 + Silverblue 特性 + 本机历史故障。点击 ▸ 展开分类,每条命令可一键复制到终端。

⚡ 快速一键体检(复制粘贴到终端)
全套体检一条命令(只读,安全):
echo "=== UPTIME ===" ; uptime ; echo "=== MEM ===" ; free -h ; echo "=== DISK ===" ; df -hTx tmpfs ; echo "=== TOP5 MEM ===" ; ps aux --sort=-%mem | head -6 ; echo "=== TOP5 CPU ===" ; ps aux --sort=-%cpu | head -6 ; echo "=== FAILED USER SVC ===" ; systemctl --user --failed --no-legend ; echo "=== FAILED SYS SVC ===" ; systemctl --failed --no-legend ; echo "=== LISTEN PORTS ===" ; ss -tlnp 2>/dev/null | head -20 ; echo "=== PRESSURE ===" ; cat /proc/pressure/* 2>/dev/null
💾 磁盘与存储 (USE: Utilization)
  • 根/数据分区使用率 · df -hTx tmpfs >85% 告警;Silverblue 根分区需预留 ostree 部署空间
  • 大文件 Top20 · sudo du -ahx / 2>/dev/null | sort -rh | head -20
  • ostree 部署层 · rpm-ostree status 查看当前/历史部署,占用空间,是否待重启生效
  • journal 日志占用 · journalctl --disk-usage · 清理: sudo journalctl --vacuum-time=7d --vacuum-size=500M
  • 用户级 journal · journalctl --user --disk-usage · 清理: journalctl --user --vacuum-time=7d
  • Podman 卷占用 · podman system df -v rootless 容器存储
  • 包缓存清理(只查) · rpm-ostree cleanup -m --preview · 执行: rpm-ostree cleanup -m
  • inode 耗尽检查 · df -i 使用率不高但写入失败常因 inode 满
🧠 内存 (USE: Saturation/Errors)
  • 内存使用 · free -h 关注 available 而非 free(含缓存可回收)
  • 内存压力 PSI · cat /proc/pressure/memory some/full > 10ms 表示真实压力
  • OOM 记录(内核) · sudo dmesg -T | grep -iE 'oom|killed process'
  • OOM 记录(用户服务) · journalctl --user -g 'out of memory|killed' --since '24h ago'
  • Top 内存进程 · ps aux --sort=-%mem | head -11
  • swap 使用 · swapon --show · vmstat: vmstat 1 5
⚡ CPU 与负载
  • 系统负载 · uptime && cat /proc/loadavg 负载 > 核数 ×1.5 需关注
  • CPU 压力 PSI · cat /proc/pressure/cpu
  • 核心数 · nproc
  • Top CPU 进程 · ps aux --sort=-%cpu | head -11
  • 上下文切换/中断 · vmstat -w 1 5 · 中断: watch -n1 'cat /proc/interrupts'
  • 进程树(僵尸检查) · ps -ef --forest | grep -w Z
🌐 网络 (黄金信号: 延迟/流量/错误)
  • 接口概览 · ip -br a
  • 路由表 · ip route · 默认网关: ip route show default
  • DNS 解析 · resolvectl status · 测试: resolvectl query google.com
  • 外网连通 · ping -c3 -W2 1.1.1.1 · DNS: ping -c3 8.8.8.8
  • Tailscale 状态 · tailscale status · 诊断: tailscale netcheck
  • 网卡错误/丢包 · ip -s link 关注 errors/dropped 持续增长
  • 当前连接 · ss -tunap | head -30
  • FRP 隧道日志 · journalctl --user -u frpc -n 50 --no-pager
  • 抓包诊断 · sudo tcpdump -i any -n -c 50 port 80
⚙️ systemd 服务
  • 失败的用户服务 · systemctl --user --failed
  • 失败的系统服务 · systemctl --failed
  • 重置失败计数 · systemctl --user reset-failed
  • 单服务详情 · systemctl --user status NAME
  • 服务启动日志 · journalctl --user -u NAME -n 100 --no-pager
  • 启动耗时分析 · systemd-analyze blame | head · systemd-analyze critical-chain
  • oneshot 假阳性排查 · is-active 对 oneshot 误报,改用: systemctl --user show NAME --property=Result,ActiveState
🔌 端口与进程
  • 监听端口 · ss -tlnp · 含 UDP: ss -tulnp
  • 端口被谁占用 · sudo ss -tlnp | grep :9800 · sudo lsof -i :9800
  • 查进程 · pgrep -af 'pattern' · 详情: ps -fp PID
  • 僵尸进程 · ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/'
  • 打开文件数 · lsof | wc -l · 单进程: ls /proc/PID/fd | wc -l
📜 日志与错误
  • 用户级近期错误 · journalctl --user -p err -n 50 --no-pager
  • 系统级近期错误 · sudo journalctl -p err -n 50 --no-pager
  • 按关键词搜 · journalctl --user -g 'keyword' --since '1h ago'
  • 内核日志 · sudo dmesg -T --level=err,warn | tail -30
  • hub 服务日志 · journalctl --user -u hub -n 100 --no-pager
  • 实时跟踪 · journalctl --user -f
🛡️ 安全与更新 (Silverblue)
  • 检查可用升级 · rpm-ostree upgrade --check
  • 当前部署状态 · rpm-ostree status 看是否需重启生效
  • 自动更新服务 · systemctl status rpm-ostreed
  • 已分层(layered)包 · rpm-ostree status -b | grep layered
  • 防火墙 · sudo firewall-cmd --list-all Silverblue 用 firewalld
  • SELinux 状态 · getenforce · AVC 拒绝: sudo ausearch -m avc -ts recent
  • 最近登录 · last -n 10 · 失败: sudo lastb -n 10
  • SSHD 配置检查 · sudo sshd -T 2>\&1 | grep -iE 'permitroot|passwordauth'
💾 备份与快照
  • 查看可回滚点 · rpm-ostree status deployments 段列出当前/上一部署
  • 回滚到上一部署 · rpm-ostree rollback 重启后生效;升级出问题时首选
  • 修复 OP 代理 · 不会重启 opencode.service，不会杀正在执行的 OP 任务
  • 部署差异 · rpm-ostree db diff 对比当前与上一部署的包变化
  • 关键数据备份检查 · du -sh /mnt/ai/* 2>/dev/null | head
⚠️ 本机已知故障点 (从历史踩坑提取,优先排查)
  • hub.service 端口冲突 · systemctl --user status hub && ss -tlnp | grep :9800 手动启动实例占用 9800 → systemd 实例 bind 失败循环重启。先 kill 手动进程再 systemctl restart
  • opencode.json 模型未注册 · opencode run 'test' --print-logs 2>\&1 | grep -i 'not found\|error' ProviderModelNotFoundError = provider.models 缺该模型,需手动加
  • ydotool-bridge 双实例 · pgrep -af ydotool-bridge 应只有一个;Hyprland exec-once + systemd 双启动 → 端口 24801 冲突
  • FRP 代理未注册 · journalctl --user -u frpc -g 'new proxy' --since '1h ago' 本地能连不代表远端转发通,优先 Tailscale 直连
  • Letta NLTK 初始化阻塞 · curl -s localhost:8283/v1/agents/ | head connection reset = NLTK 初始化,传 http_proxy 等 60s+
  • default_agent 大小写 · opencode agent list | grep -i primary Bob ≠ bob;agent 名区分大小写
  • Silverblue /usr 只读 · 写操作用 rpm-ostree(需重启)或用户级 pip/cargo/npm;命令是 rpm-ostree(连字符)不是 rpm ostree
